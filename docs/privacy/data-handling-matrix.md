# Data Handling Matrix

What Your Name for Threads stores, where, whether any of it leaves your browser, and how you remove it.

This is the reference the public privacy statements are written from: `PRIVACY.md`, the About & Privacy page, the GitHub Pages privacy page and the store disclosures. If one of them disagrees with this table, one of them is wrong and must be fixed before release.

It describes what the code does, not what was intended. `tests/repo/data-handling-matrix.test.ts` checks what a machine can: the storage keys the code really writes, what a real JSON backup really contains, that nothing in `src/` uses a network API (apart from the page observer described in the last row), and that the two statements most likely to go stale (the identity cache sweep and the Recovery dump) are revisited when the code changes. It cannot check the wording of the prose.

**Nothing is sent to the developer.** The extension has no developer-run server, analytics, telemetry, crash reporter, advertising or cloud sync. It contains no code that makes a network request, and its manifest asks for `storage` and for host access to `https://www.threads.com/*` only. Data leaves your browser only when you do something with it: export a backup, copy diagnostics, or paste either one somewhere.

## Data

| Data | Purpose | Stored where | Sent to the developer? | In a JSON Backup? | Retention | User control |
| --- | --- | --- | --- | --- | --- | --- |
| **Threads username** | Says which account a nickname belongs to; shown beside nicknames in the Dashboard; lets the extension recognise a profile, post author or reply on the page. | `chrome.storage.local`: inside the Directory (`directories`, on every contact and tombstone) and in the identity cache (`identityCache`, see that row). Your own username is also in session storage (see "Current-account state"). | No. | Yes: on every contact and tombstone, and as the exporting account (`exportedBy`). | Directory copies: until you clear this account's data. Cache copies: see "Identity cache". | Delete Contact removes the nickname and note but the tombstone keeps the username. Clear this account's data removes contacts and tombstones. Removing the extension removes everything. |
| **Numeric Threads ID** | The stable identity: a username can change, the number cannot, so a nickname follows a person through a rename. Also says which Directory belongs to which of your accounts. | `chrome.storage.local`: the Directory (`threadsUserId` on contacts and tombstones, plus its `identityIndex` and `identityConflicts`), `accountBindings` (your own number to a Directory ID), and `identityCache`. Your own number is also in session storage. | No. | Yes: on contacts and tombstones and as the exporting account. The index, the conflicts and the account bindings are not exported. | Same as the username. | Same as the username. |
| **Nickname** | The point of the extension: shown in place of the display name on profiles, in the feed, in replies and in quotes, wherever Settings allows. | `chrome.storage.local`: `directories`, on the contact. | No. | Yes. | Until you edit, delete or clear it. Deleting a contact discards the nickname. | Edit or delete on a profile or in the Dashboard directory. Clear this account's data. |
| **Note** | Your own reminder about a person. Never shown on Threads pages. | `chrome.storage.local`: `directories`, on the contact. | No. | Yes. | Until you edit, delete or clear it. Deleting a contact discards the note. | Edit or delete in the Dashboard. Clear this account's data. |
| **Tombstones** | Remember that a contact was deleted or merged, so importing an older backup does not quietly bring it back. Holds the username, the numeric ID if known, the contact ID, when it was created and deleted, why, and the merge target. Never the nickname or the note. | `chrome.storage.local`: `directories`, in the Directory's `tombstones`. | No. | Yes. | Kept until you clear this account's data. Nothing expires them. | Clear this account's data. On import you can choose to keep deleted contacts deleted. |
| **Identity cache** | Recognise a username and its numeric ID from what the Threads page shows, before you have nicknamed anyone, and confirm which account is signed in. Holds the username, the ID, how it was observed and when, and when it expires. | `chrome.storage.local`: `identityCache`. Shared by every Threads account in this browser profile, not one per Directory. Filled from every profile, post and reply you view, not only from accounts you nickname. No size limit. | No. | No. | An entry counts as expired 30 days after it was observed and is deleted the next time that same username is looked up. The entries are not swept: one for a username nobody looks up again stays until the extension is removed. | None in the extension. Clear this account's data deliberately leaves it, because it is not part of any Directory. Removing the extension removes it. |
| **Current-account state** | Which Threads account each open Threads tab and Dashboard tab belongs to, so private data opens only for an account the extension has confirmed. Holds the tab ID, the state, your own username and numeric ID, timestamps, the browser's own identifier for the page a tab is showing (`documentId`, which changes on every reload), and for the Dashboard a random session ID and the ID of the Dashboard tab. | `chrome.storage.session` (`tpd:tabContexts`, `tpd:dashboardSessions`): memory only, never written to disk. | No. | No. | Cleared when the browser restarts. Also dropped when the tab closes or the account can no longer be confirmed. A Dashboard session ends when its Threads tab reloads, leaves Threads, closes or stops proving the same account, with no waiting period, and is removed when its Dashboard tab closes. | Close the tab, or restart the browser. |
| **Integration status** (in memory only) | Lets the popup and About & Privacy say when part of the Threads integration (the profile page, or nicknames on posts) is unavailable, so you are not left guessing why a nickname is missing. Holds the tab ID and, for each of those two parts, "ready" or "degraded". Only tabs with something wrong are kept. No username, address, error text or page content can be in it: every value is one of a fixed list. | `chrome.storage.session` (`tpd:tabSurfaces`): memory only, never written to disk. | No. | No. | Cleared when the browser restarts. Also dropped when the tab closes or starts loading a page, and when the part that failed works again. | Close the tab, or restart the browser. |
| **Settings** | Whether the extension is on, and on which places (profile, feed, replies, quotes) nicknames are shown. On/off values only. | `chrome.storage.local`: `settings`. | No. | No. | Until you change it or remove the extension. | Dashboard, Settings. |
| **First-run tour flag** | Remember that the tour was finished, so it is not shown again. One on/off value. | `chrome.storage.local`: `onboarding`. | No. | No. | Until the extension is removed. | The tour can be replayed from About & Privacy. |
| **Last-seen notice ID** | Remember which major-update notice the popup last showed, so the same one is shown once and not again. One short ID; v1.0 configures no notice, so nothing is stored until a release adds one. | `chrome.storage.local`: `lastSeenNoticeId`. | No. | No. | Until the extension is removed. | Dismiss the notice. It is only ever replaced by the ID of a newer one. |
| **Diagnostic event codes** | Let you see which part failed, and paste that into a bug report if you choose to. Each event is a code from a fixed list of 9, a component from a fixed list of 7, a timestamp, the extension version and sometimes a state. No free text, no usernames, no notes and no error messages: events are rebuilt from an allowlist when they are written and again when they are read. | `chrome.storage.local`: `diagnostics`. | No. Copying them is a manual action you take, and nothing is attached to an issue for you. | No. | The newest 20 are kept; older ones are dropped. | About & Privacy: Clear diagnostics. Copy diagnostics is yours to paste or not. |
| **Copied diagnostics** | What "Copy diagnostics" puts on your clipboard, for you to paste into a bug report if you choose to. It is built when you press the button, from fixed labels and numbers: the extension version, the browser family and its major version (for example "Chrome 153"), the operating system family (Windows, macOS, Linux, ChromeOS or Other), the storage and backup format numbers, the account and Recovery states, how many contacts, deleted-contact records and pending conflicts the current account's Directory holds, whether each part of the Threads integration is working, and the recent event codes described above. No username, ID, nickname, note, address or error message can be in it. | Nowhere: the text goes to your clipboard and the extension keeps no copy. | No. Copying it is a manual action you take, and nothing is attached to an issue for you. | No. | As long as it stays on your clipboard or where you paste it. The extension cannot remove it. | Copy diagnostics is yours to press, and to paste or not. It is public if you paste it into a public issue. |
| **Backup file** | A copy you keep, to move or recover your Directory. Plain, unencrypted JSON: a format tag and version, the exporting account's username and numeric ID, the Directory ID, the export time, every contact (username, ID, nickname, note, timestamps) and every tombstone. | Wherever you save the download. The extension keeps no copy. | No. | It is the backup. | As long as you keep the file. The extension cannot delete it. | You choose when to export, where it goes and who sees it. It holds private nicknames and notes: do not post it publicly. |
| **Recovery dump** | The raw stored data, saved before anything damaged is cleared, so a person can look at it by hand. It is a separate file, `your-name-for-threads-recovery-...json`, that the Backup importer refuses, and nothing in the extension reads it back. For one damaged Directory it holds only that account's Directory record and its binding, exactly as stored and unchecked. When the root of storage is damaged nothing can be scoped, so it holds all of storage, every account's data included. It may hold private nicknames, notes, usernames and internal IDs. | Only where you save the download. The extension keeps no copy. | No. | No: the Backup importer rejects it. | As long as you keep the file. The extension cannot delete it. | Created only when you choose "Export recovery data" on the Recovery page. It is yours to keep private: do not post it publicly. |
| **Threads page traffic** (in memory only) | The extension can only learn a username and its numeric ID from what the Threads page itself loads. A script running in the page wraps `fetch` and `XMLHttpRequest` on `threads.com`, reads each successful JSON response as it passes, keeps only username and ID pairs, and hands those to the extension. It makes no requests of its own, does not alter the responses and does not keep the rest. | Nowhere. Only the pairs it finds are kept, as described under "Identity cache". | No. | No. | Not kept. | Turn the extension off in Settings: the observer stays installed but stops recording. |

## Storage keys

The real keys, cross-checked by the test against what the code writes.

| Area | Key | Holds |
| --- | --- | --- |
| `chrome.storage.local` | `schemaVersion` | The number of the storage format. |
| `chrome.storage.local` | `directories` | Every Directory: contacts, tombstones, identity index, identity conflicts. |
| `chrome.storage.local` | `accountBindings` | Your account's numeric ID to a Directory ID. No username. |
| `chrome.storage.local` | `identityCache` | The identity cache. |
| `chrome.storage.local` | `settings` | Settings. |
| `chrome.storage.local` | `onboarding` | The first-run tour flag. |
| `chrome.storage.local` | `lastSeenNoticeId` | The ID of the last major-update notice the popup showed. |
| `chrome.storage.local` | `diagnostics` | Diagnostic event codes. |
| `chrome.storage.session` | `tpd:tabContexts` | Current-account state, per Threads tab. |
| `chrome.storage.session` | `tpd:dashboardSessions` | Current-account state, per Dashboard session. |
| `chrome.storage.session` | `tpd:tabSurfaces` | Integration status, per Threads tab. Only tabs with something wrong. |

The extension never uses `chrome.storage.sync`, so nothing replicates through your browser account. Data written by pre-release builds under older root keys (`contacts`, `tombstones`, `identityIndex`, `identityConflicts`, `directory`) is migrated and those keys are removed.
